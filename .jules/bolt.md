## 2025-02-26 - O(N) Database Queries in Discovery Loop (N+1 Problem)
**Learning:** Using `get_list()` with a filter inside a `for` loop (e.g., scanning thousands of files) creates a severe N+1 query bottleneck. While `get_list` works fine for single lookups, inside a loop it causes massive network overhead. Pre-fetching the data with `get_full_list()` and doing an in-memory dictionary lookup changes this to an O(1) operation. However, silently ignoring a `get_full_list()` failure (like a DB connection drop) and falling back to an empty dictionary will cause the service to incorrectly think all files are new, resulting in massive duplicate inserts.
**Action:** Always pre-fetch records with `get_full_list()` before loops to optimize database access, but handle exceptions explicitly and fail fast if the pre-fetch fails to avoid destructive database duplication.
